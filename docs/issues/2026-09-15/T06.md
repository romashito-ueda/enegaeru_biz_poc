# [TRACE PoC] UIを非同期計算へ切り替え、保存データと結果の版を管理する

GitHub公開済み: [#8](https://github.com/romashito-ueda/enegaeru_biz_poc/issues/8)

## 目的
計算中も条件編集でき、古い結果と新しい条件を取り違えずに提案できるようにする。

## 共通前提
対象は産業用太陽光・蓄電池を提案する販売施工店/EPC向けTRACE PoC。モック・固定値を許容し、計算・判断の整合性を検証する。契約電力/基本料金削減は対象外。既存のローカルReact/Vinext PoCを[T00](T00.md)で取り込み、Python/PySAMを接続する。実データ調達は初期PoCのブロッカーにしない。

## 実装範囲
- components/workspace.tsxの同期useMemo(simulate)を共通engine-clientへ移す。最初はT03のPV単独結果で接続し、T04/T05完了後に年次結果を接続する。
- 編集中/未計算/待機/計算中/完了/失敗/キャンセルを表示する。条件変更後の結果には使用条件と旧結果であることを表示する。
- 入力revision/hashとjobIdで遅れて返る応答を識別し、古い要求の応答で最新画面を上書きしない。
- localStorageとJSONバックアップのschemaVersionを更新し、旧案件を退避して移行する。旧計算値を新エンジンの検証済み結果と扱わず、再計算待ちにする。
- 設定・保存・比較・CSV取込・WebMCPを同じ入力検証経路に集約する。エンジン未起動時は接続方法と再試行を示す。

## 完了条件
- [ ] 編集A→実行A→編集B→実行B→Aが遅れて完了、の順でもBの結果が保持される。
- [ ] 計算中に条件編集、画面移動、キャンセルができ、操作が同期計算で長時間停止しない。
- [ ] 旧JSONの需要・設備・保存案が移行でき、非対応のpeak/gridCharge設定は変更理由とともに確認対象になる。
- [ ] CSV/詳細入力/WebMCPを含む全変更経路で設備不一致を防ぐ。
- [ ] PV単独の早期E2Eが動き、最終完了時にはT04/T05の結果でグラフ・保存・書出しが動作する。

## 検証
非同期応答競合、障害/再試行、旧データ移行、主要操作のブラウザ確認。

## 主な対象
components/workspace.tsx, components/conditions.tsx, components/energy-charts.tsx, lib/exports.ts。新設候補: hooks/use-simulation-job.ts。

## 対象外
認証、共同編集、クラウド保存、UI全体の無関係な書換え。
