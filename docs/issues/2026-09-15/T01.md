# [TRACE PoC] 入出力契約・前提条件・時系列と検証用データを定義する

## 共通前提
対象は産業用太陽光・蓄電池を提案する販売施工店/EPC向けTRACE PoC。モック・固定値を許容し、計算・判断の整合性を検証する。契約電力/基本料金削減は対象外。既存のローカルReact/Vinext PoCを[T00](T00.md)で取り込み、Python/PySAMを接続する。実データ調達は初期PoCのブロッカーにしない。

## 実装範囲
- 現在のReact/Vinext PoCを出発点とし、Python計算サービスと共有するバージョン付きJSON Schemaを定義する。TypeScriptとPythonの両方で同じJSON fixtureを検証する。
- Site/Roof/Weather/Load/Equipment/Tariff/EvaluationPolicy/DecisionConstraints/UncertaintyScenario/SimulationResultを分ける。値に単位、source、assumed/derived/observed/mock、確認状態、対象期間、更新日時を保持する。データ取得済みと現地確認済みを混同しない。
- canonical時系列はJST、30分、区間開始時刻、電力量kWh。エンジン境界の平均電力kWと日射W/m²を明示する。通常年17,520区間をPoCの受理対象にし、うるう年・欠損・重複・混在時間帯は明示的エラーにする。1時間から変換した場合は元解像度と変換方法を残す。
- 発電入力は気象からの再計算と設備に紐づく絶対AC実績を区別する。絶対AC実績のまま容量・PCSを変える操作は全経路で拒否し、再計算用入力への切替を求める。
- 投資条件は自己所有・税前・借入なし・20年。契約電力と基本料金削減は評価対象外。需要・気象・設備単価等のmockを許可し、実測値に昇格させない。
- 機器費をPV kW、PV PCS kW、蓄電池kWh、蓄電池PCS kW、工事固定費等に分け、補助金・更新費の対象と時期を定義する。予算、回収条件、評価目的、想定需要変化、許可屋根面を入力可能にする。

## 完了条件
- [ ] 共通fixtureがTypeScript/Python両方で受理され、不正単位・時系列・設備不一致のfixtureが両方で拒否される。
- [ ] 変換前後の区間・月・年の電力量が一致し、方位は北0°/東90°/南180°/西270°に統一される。旧PoCの方位表現を明示的に変換する。
- [ ] 工場・物流・小売の合成入力と、候補順位が変わる/変わらない質問用ケースがあり、作成方法とモック表示が記録される。
- [ ] 未確定値の範囲と実際に確認された値が区別され、入力hashにモデル・単価・前提の版を含める。
- [ ] 旧Params/Projectから新契約への対応表があり、移行できない項目を暗黙に捨てない。
