# エネがえるBiz 機能調査と TRACE PoC 対応表

確認日：2026-09-08。公開されている公式サイト、マニュアル、FAQに基づく。契約アカウントでの現行UIの実査は行っていない。データの調達可否・ライセンス・網羅性は今回の調査対象外。

## 結論

主要な提案業務は「需要を設定 → 設備を調整 → 導入案を比較 → 提案資料を出力」に整理できる。TRACEではこの流れを、合成データと独自の簡易計算で操作可能にした。商用版の全機能・精度の再現ではなく、主要な操作と意思決定を検証するPoCである。

エネがえるBiz自体が既に需要テンプレート、蓄電池、長期収支、Excel出力を備える。その有無で差別化するのではなく、条件変更から判断までの往復を減らし、根拠とトレードオフを同じ作業画面で理解できる体験を設計した。

## PoCに追加したUX

1. 需要・料金を共通化した3案比較。選択中の案とカスタムの違いが見える。
2. 主要条件と結果を隣接配置し、詳細条件だけ別パネルに段階的に表示。
3. 年間削減額から比較へ、回収年数から長期収支へ進める。
4. 蓄電池の追加投資を、同じ太陽光容量・同じ需要の蓄電池なしケースと比較。
5. 余剰量、CO₂、追加投資、維持更新費を併記。蓄電池の増設を無条件に推奨しない。
6. 画面の計算結果をそのまま提案書・Excelへ出力。
7. CSV不備は行番号と修正方法を表示。入力はブラウザ内で処理。

これらは優位性の仮説。実製品との差を実測した結果ではない。比較対象にも同様の機能が存在する可能性がある。

## 優位性の検証計画

対象：営業・設計担当者5〜8名。製品習熟度を揃え、同じサンプル案件で順序を入れ替えて比較。

| タスク                        | 測定値                           | PoCでの目標（未測定） |
| ----------------------------- | -------------------------------- | --------------------- |
| デマンドなし案件の初回試算    | 完了時間・入力ミス               | 3分以内               |
| 太陽光のみ／蓄電池ありの判断  | 比較完了時間・選択理由の正答     | 2分以内、80%以上      |
| 削減額の根拠を説明            | 自家消費と自給率を混同しない割合 | 90%以上               |
| 料金が20%変動した場合の再提案 | 画面往復数・再入力数             | 共通条件の入力1回     |
| 提案資料の作成                | 出力時間・画面との数値不一致     | 1分以内、不一致ゼロ   |

## 計算モデルと意図的な制約

- 2025年の365日×48区間。各区間の電力量はkWh、グラフの電力はkW（kWh÷0.5h）。時刻はJSTとして扱うタイムゾーンなしのラベル。
- 需要は年間または月別総量を維持して合成波形へ配分。祝日なし。CSVは連続した17,520行を要求。
- 発電は合成天候と日長、原単位、方位・傾斜の簡易係数から生成しPCSで制限。実際の日射DBは使用しない。
- 蓄電池は利用可能残量ゼロから開始し、年内で連続追跡。非常用の確保分は利用可能容量から控除。充放電の各効率は往復効率の平方根。同一区間で充電と放電を併用しない。
- 太陽光と系統由来の蓄電量を分別管理し、自家消費率に系統由来の放電を混ぜない。
- 基本料金のピーク方式は年間最大値×12か月。実務でのローリング契約電力更新や月別の制度は再現しない。
- 長期収支は初年度の効果に上昇・劣化率を掛ける概算。設備別劣化、毎年の運転再計算、融資、税、廃棄費、金利、PPA契約は未実装。
- 保存はlocalStorage。端末をまたぐ共有、機密保護、永続保管、組織権限、監査ログは本番化で別途設計。
